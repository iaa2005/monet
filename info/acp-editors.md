# Code Monet в редакторах через ACP

Code Monet умеет работать как агент по протоколу
[Agent Client Protocol](https://agentclientprotocol.com/): редактор запускает
приложение с флагом `--acp`, они говорят JSON-RPC по stdio, и сессия ведётся из
редактора. Движок тот же самый — те же инструменты, тот же workspace, те же
разрешения, — просто без нашего окна.

## Что нужно

Собранное приложение. В dev это `out/main/index.js`, в собранной версии — сам
исполняемый файл.

Проверить, что режим поднимается:

```bash
npm run smoke:acp
```

## Zed

В `~/.config/zed/settings.json`:

```json
{
  "agent_servers": {
    "Code Monet": {
      "type": "custom",
      "command": "C:\\Path\\To\\Code Monet.exe",
      "args": ["--acp"],
      "env": {}
    }
  }
}
```

Для запуска из исходников вместо этого:

```json
{
  "agent_servers": {
    "Code Monet (dev)": {
      "type": "custom",
      "command": "node_modules/.bin/electron",
      "args": ["out/main/index.js", "--acp"],
      "env": {}
    }
  }
}
```

Дальше — новый разговор в панели Agent.

## VS Code и JetBrains

Оба работают через расширения-клиенты ACP; настройка сводится к тому же:
команда запуска плюс аргумент `--acp`. Конкретный пункт настроек зависит от
расширения — общего стандарта на имя поля пока нет.

## Что уже работает

- `initialize` — согласование версии и возможностей
- `session/new` — сессия с рабочей папкой от редактора
- `session/prompt` — ход агента, ответ и вызовы инструментов приходят
  потоком как обновления сессии
- `session/cancel` — прерывание
- **Запрос разрешений** — запись файла или команда всплывают диалогом
  в редакторе. Ничего не одобряется за пользователя: если редактор не может
  показать запрос, ответ — отказ.

## Чего пока нет

- **Картинки и звук.** `initialize` честно объявляет `image: false` и
  `audio: false`, чтобы редактор не присылал то, что мост молча выбросит.
- **`session/load`.** Продолжить прошлую сессию из редактора нельзя, только
  начать новую.
- **Режимы и выбор модели из редактора.** Модель берётся активная из настроек
  приложения.

## Две вещи, выясненные экспериментом

Их стоит знать тому, кто будет это трогать дальше.

**`process.stdin` в главном процессе Electron не работает.** Поток
рапортует `readable: true` и сразу отдаёт `end` — данных не приходит вообще.
Адаптер читает дескриптор 0 напрямую (`createReadStream(fd: 0)`), и вот это
работает: проверено на Windows, включая пакетную запись и сообщение,
разорванное между двумя чанками.

**stdout — это и есть протокол.** Приложение логирует в него из десятка мест
(`[mcp] …`, `[routines] …`, `[podman] …`), и одна такая строка посреди потока
JSON-RPC убивает сессию. В режиме `--acp` stdout захватывается до всех прочих
импортов, а `console.*` целиком уходит в stderr. Тест это проверяет отдельной
проверкой: «stdout carried ONLY protocol messages».
