## 1. Что это такое

Kimi Code CLI от Moonshot AI — агент-кодер для терминала, очень близкий по идеологии к Claude Code,
но с несколькими вещами, которых у Claude Code нет вообще. Монорепозиторий на pnpm:
**5 приложений + 17 пакетов**, Node ≥ 24.15.

Масштаб, для калибровки:

| | Kimi Code | Code Monet (desktop) |
|---|---|---|
| Исходники (без тестов и вендора) | **2452** файла | **278** файлов |
| Вендорный/чужой код | нет | 1497 файлов (`vendor/leaked`) |
| Тесты | **1116 файлов** vitest | **0** unit-тестов (4 smoke-зонда) |
| Лицензия | MIT | — |

Разница в тестах — это не придирка к цифре. Это единственная строка таблицы, которая объясняет,
почему у них можно безопасно рефакторить ядро, а у нас каждый баг ловится руками.

## 2. Чего нет у нас — по убыванию ценности

### 2.1. Goal mode — автономный многоходовой режим ⭐ главное

Это самая крупная архитектурная новинка, и у Claude Code её тоже нет.

Обычный промпт говорит *что сделать дальше*. Цель говорит, *что должно стать правдой*.
Пользователь пишет `/goal Почини все падающие тесты checkout и прогони набор`, и рантайм
сам гоняет ходы, пока цель не достигнута.

Устройство (`packages/agent-core/src/agent/goal/`, `injection/goal.ts`, `tools/builtin/goal/`):

- **Конечный автомат из 4 состояний**: `active` / `paused` / `blocked` / `complete`.
  Состояния `cancelled` нет намеренно — отмена это удаление цели.
- **Goal driver** гоняет по одному обычному ходу за раз; после каждого читает статус.
  Пока `active` — дописывает continuation-prompt и запускает следующий.
- Модель **не может завершить цель словами**. Только структурированным сигналом через
  инструмент (`update-goal`). Иначе рантайм просто продолжит.
- **Бюджет токенов** (`set-goal-budget`) — цель уходит в `blocked` при исчерпании.
- **Очередь целей** (`/goal next`) — следующая стартует автоматически после завершения текущей.
  Агент не видит очередь, пока работает над текущей.
- В prompt-режиме коды выхода: `0` выполнено, `3` заблокировано, `6` пауза.

Отдельно отмечу деталь, которая нам прямо в тему: цель инжектится в контекст
**обёрнутая в `<untrusted_objective>`**, с явным комментарием, что это данные задачи,
а не инструкции, и они не перебивают system/developer-сообщения и правила разрешений.
Три уровня напоминания по статусу: полное для `active`, лёгкое для `blocked`, охранительное
для `paused`.

У нас ближайший аналог — рутины, но они по расписанию, а не «работай, пока не сойдётся».

### 2.2. Веб-GUI + документированный API ⭐

`kimi web` поднимает **один процесс**, который отдаёт и REST+WS API, и статику веб-интерфейса
с того же origin, и открывает браузер. При работающем сервере:

- `GET /openapi.json` — REST-документация
- `GET /asyncapi.json` — документация WebSocket

Веб-UI на Vue 3 (`apps/kimi-web`), и это не урезанная версия TUI:

- **Мобильная вёрстка** — `components/mobile/`, `useIsMobile`, отдельные шиты настроек и
  переключателя. То есть с телефона.
- **Настоящий PTY-терминал** в браузере (xterm + маршрут `terminals.ts`, сессионно-скоупленный,
  с защитой от выхода за пределы workspace).
- `GoalStrip.vue`, `SideChatPanel.vue`, `ConversationToc.vue` (**оглавление длинной переписки**),
  `AgentDetailPanel.vue`, `swarmGroups.ts`, `CronNotice.vue`, `DesignSystemView.vue`.
- `/web` из TUI — **переносит текущую сессию в браузер**. Непрерывность TUI ↔ web.

Безопасность сервера продумана заметно лучше нашего `dev-api.ts`
(`packages/kap-server/src/security/bindClassify.ts`):

| Класс адреса | Что применяется |
|---|---|
| `loopback` (127/8, ::1) | только токен |
| `lan` (RFC1918, link-local) | усиление рекомендуется |
| `public` (всё остальное, **включая `0.0.0.0`**) | обязательный пароль, TLS opt-out, rate-limit на ошибки аутентификации, понижение опасных эндпоинтов, security-заголовки |

Плюс проверка на DNS-rebinding (`--allowed-host`), персистентный токен с ротацией
(`kimi web rotate-token`), несколько инстансов на одном home с автоподбором порта.

Наш `dev-api.ts` имеет 4 гейта (env-флаг, отказ в packaged, 127.0.0.1, токен на загрузку) —
это правильно для dev-инструмента, но у них это продуктовая фича с моделью угроз.

### 2.3. Слой возможностей моделей (`kosong`) ⭐ прямо чинит наш баг

У них `ModelCapability` на каждую модель:

```ts
image_in, video_in, audio_in, thinking, tool_use,
max_context_tokens, max_input_tokens?, dynamically_loaded_tools?
```

Плюс **импорт каталога models.dev** (`packages/kosong/src/catalog.ts`, 509 строк) —
провайдер добавляется, и модели с их возможностями подтягиваются сами.
Это ровно то, что вы просили раньше: «не хочу вводить модели в провайдере в селекторе,
надо чтобы предлагал из существующих».

А теперь наш код, `desktop/src/main/ipc/chat.ts:59`:

```ts
const vision = /anthropic\.com/i.test(p.baseURL) || p.kind === "openrouter";
return new Set(vision ? ["text", "image"] : ["text"]);
```

Мы **угадываем поддержку зрения регуляркой по URL провайдера**. Любой OpenAI-совместимый
шлюз с моделью GPT-4o получит `["text"]`, и картинка пользователя молча уедет в
`stashUnsupported()` вместо того, чтобы дойти до модели. Это баг, который сейчас никак не виден.

Ещё у них `max_input_tokens` отдельно от `max_context_tokens` (пример из кода: gpt-5 — окно 400k,
но вход ограничен 272k) — компакция считает бюджет по правильному числу.

### 2.4. Конвейер политик разрешений ⭐ структурно чинит наш класс багов

У них разрешения — не одна функция, а **17 именованных политик** в
`packages/agent-core/src/agent/permission/policies/`:

```
deny-all                       yolo-mode-approve
auto-mode-approve              auto-mode-ask-user-question-deny
file-access-ask                git-cwd-write-approve
plan-mode-guard-deny           plan-mode-tool-approve
exit-plan-mode-review-ask      goal-start-review-ask
agent-swarm-exclusive-deny     swarm-mode-agent-swarm-approve
session-approval-history       user-configured-rules
pre-tool-call-hook             default-tool-approve
fallback-ask
```

Каждая — отдельный файл с одним решением. Вспомните баг, который мы чинили: «auto-режим писал
куда угодно на диске», потому что Edit/Write разрешались **по имени инструмента**, а путь
не проверялся. При такой схеме `file-access-ask` — отдельная обязательная ступень конвейера,
и обойти её, разрешив инструмент по имени, структурно невозможно.

Различие YOLO и Auto у них тоже тоньше нашего: **YOLO всё равно спрашивает** про
чувствительные файлы (`.env`, SSH-ключи) и выход из Plan mode. Auto — не спрашивает ничего.
У нас `bypassPermissions` — это сразу «всё можно».

Правила в конфиге поддерживают паттерны аргументов: `deny = "Bash(rm -rf*)"`.

### 2.5. AgentSwarm — рой по шаблону

Вы просили «рой агентов как в вендоре». У Kimi другая, более простая и, на мой взгляд,
более практичная модель, чем наши `TeamCreate`/`SendMessage`:

- `prompt_template` с плейсхолдером `{{item}}` + массив `items` → по субагенту на элемент.
- До **128** субагентов, ожидание всех, агрегированный отчёт.
- **Разгон конкурентности**: 5 стартуют сразу, дальше по одному каждые 700 мс
  (`KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY` ограничивает).
- `resume_agent_ids` — можно возобновить существующих субагентов.
- Жёсткое правило: если модель вызывает `AgentSwarm`, это **единственный** вызов в ответе
  (политика `agent-swarm-exclusive-deny`).
- Режим роя: `/swarm on|off`, `/swarm <задача>` — включает, шлёт промпт, по завершении выключает.

Три встроенных типа субагентов с реально разными правами:
`coder` (всё), `explore` (**только чтение**, файлы не меняет), `plan` (даже без shell).

### 2.6. ACP — интеграция с редакторами

`kimi acp` говорит на [Agent Client Protocol](https://agentclientprotocol.com/) по stdio,
и сессию можно вести из Zed, JetBrains и любого ACP-клиента. Отдельный пакет `acp-adapter`.
Для нас это потенциально способ попасть в чужие IDE без написания расширения под каждую.

### 2.7. Плагины и маркетплейс с уровнями доверия

Это зрелая версия нашего Directory:

- Четыре вкладки: Installed / Official / Third-party / Custom.
- **Бейдж доверия у каждой установки**: `kimi-official` / `curated` / `third-party`.
  Установка стороннего плагина показывает подтверждение, **по умолчанию — отмена**.
- Установка из GitHub четырьмя способами: репозиторий (последний релиз), `tree/<ref>`,
  `releases/tag/<tag>`, `commit/<sha>` — то есть можно **пришпилить к коммиту**.
- Сеть ходит только через `github.com` и `codeload.github.com`; `api.github.com` не вызывается
  (обход rate-limit без токена).
- Плагин = манифест + skills + **MCP-серверы** + **хуки** + **slash-команды**. Один пакет
  привозит всё сразу.
- Установленное **копируется** в `plugins/managed/<id>/`, запуск всегда из копии — правка
  исходной папки ни на что не влияет.
- Модель безопасности прописана явно: пути обязаны оставаться внутри корня плагина
  **после разрешения симлинков**; MCP стартуют только после `/reload`; битые манифесты
  видны в диагностике.

### 2.9. Cron-инструменты, продуманные до неприятных краёв

У нас есть рутины. У них — `CronCreate` / `CronList` / `CronDelete`, и три детали,
до которых доходят только на реальной эксплуатации:

- **Детерминированный джиттер**: повторяющиеся задачи сдвигаются на `min(10% периода, 15 минут)`,
  разовые в `:00`/`:30` — до 90 секунд. Чтобы все пользователи планеты не выстрелили ровно в час.
- **Коалесценция пропусков**: ноутбук спал, пропущено 8 срабатываний — сработает **один раз**,
  промпт завёрнут в `<cron-fire>` с полем `coalescedCount`.
- **Протухание**: повторяющаяся задача старше 7 дней срабатывает последний раз с `stale="true"`
  и удаляется. Чтобы забытый крон не молотил вечно.

## 4. Где они сделали лучше то же самое

### 4.1. Bash

- Фоновая команда по таймауту **не убивается**, а переезжает в фон
  (`bash_auto_background_on_timeout`). У нас таймаут = смерть процесса.
- Двухфазное завершение: SIGTERM → 5 секунд → SIGKILL.
- stdin всегда закрыт — интерактивные команды сразу получают EOF вместо вечного зависания.
- **`tree-sitter-bash` на чистом TypeScript** — парсер с бюджетом, итеративной материализацией
  дерева (защита от переполнения стека на длинных цепочках вроде `$((1+1+...))`) и контрактом
  «никогда не бросает». Пока подключён только в `agent-core-v2` как сервис, но это фундамент
  для точного разбора команд в правилах разрешений вместо сравнения строк.

### 4.2. Grep / Glob

Автоматически **отфильтровывают чувствительные файлы** (`.env`, приватные ключи) — причём
`include_ignored=true` снимает фильтр `.gitignore`, но **не** снимает фильтр секретов.
У нас такого нет: `ripgrep.ts` вернёт `.env`, если модель его запросит.

### 4.3. Plan mode

- В Plan mode `Write`/`Edit` разрешены **только для файла плана**, `TaskStop` запрещён полностью.
- `ExitPlanMode` принимает `options` — агент предлагает **1–3 альтернативных подхода**,
  и пользователь выбирает прямо в диалоге утверждения. У нас — approve / keep-planning.
- Выход из Plan mode требует подтверждения **даже в YOLO**.

### 4.4. Хранение сессий

`sessions/<workDirKey>/<sessionId>/agents/<agentId>/wire.jsonl` — по потоку на агента,
и в нём же **трассировка запроса**: схемы инструментов, параметры запроса, листинги MCP.
Ровно то, чего нам не хватало при отладке промптов через dev-api: можно посмотреть,
что именно ушло в модель.

Плюс `kimi export` — ZIP сессии со всеми логами для баг-репорта, и `/export-md` для человека.

### 4.5. Слоистый рендеринг переписки (`transcript`)

L1 store по агентам → L2 идемпотентные операции → L3 подписки с гранулярностью →
L4 реестр представлений без привязки к фреймворку. Плюс `groupTurns`, `foldFacts`, `paginate`.
Наш `chatStore.ts` — один плоский массив сообщений; группировка и свёртка живут в компонентах.

### 4.6. Скиллы

- **`~/.agents/skills/`** — общая межинструментальная папка скиллов, которая **не переезжает**
  вместе с `KIMI_CODE_HOME`. Появляется межагентная конвенция `.agents/`, и мы, по совпадению,
  уже в ней живём (проект лежал в `~/.agents/claude-code`).
- Четыре уровня приоритета: Project > User > Extra > Built-in.
- Аргументы: `$ARGUMENTS`, позиционные `$0`/`$1` **с поддержкой кавычек**, именованные `$<name>`,
  и `${KIMI_SKILL_DIR}`.
- Типы: `prompt` / `inline` / `flow` (только ручной вызов), `whenToUse`, `disableModelInvocation`.
- Глубина вложенности вызовов скиллов ограничена 3.

### 4.7. Явная модель доверия к файлам из репозитория

В документации по агентам есть предупреждение, которое нам стоит скопировать дословно:
файл `.kimi-code/agents/agent.md` с `override: true` **заменяет весь системный промпт**
главного агента, а файл без списка `tools` сохраняет все инструменты. Поэтому такие файлы
в свежесклонированном репозитории надо смотреть как скрипты, до запуска.

У нас, к чести, хуки сделаны правильно: `tool-hooks.ts` грузит только `<dataDir>/hooks.json`
через программный канал, и в коде явно написано почему — «репозиторный `.claude/settings.json`
может назвать произвольные shell-команды, а PreToolUse-хук выполнит их до того, как пользователь
что-то увидит». **Но шапка того же файла (строки 12–15) утверждает обратное**: что работают
`<workspace>/.claude/settings.json` и `~/.claude/settings.json`. Комментарий устарел и
противоречит и коду, и вашему решению уйти от `.claude`. Это надо поправить — иначе следующий
читатель поверит шапке.

## 5. Что я предлагаю взять, по порядку

Отсортировано по отношению «польза / стоимость».

**Сразу, дёшево:**

1. **Capability моделей вместо регулярки по URL.** Заменить `activeModalities()` на таблицу
   возможностей на модель, как в `kosong/capability.ts`. Чинит реальный молчаливый баг
   с картинками на не-Anthropic провайдерах.
2. **Импорт каталога models.dev** в менеджер провайдеров — вы этого просили, у них готовый
   рабочий образец на 509 строк.
3. **Фильтр секретов в Grep/Glob** — `.env`, `id_rsa` и прочее не должны попадать в выдачу
   даже по прямому запросу модели.
4. **Починить шапку `tool-hooks.ts`** — она противоречит коду.
5. **Джиттер и коалесценция в рутинах** — три небольших правила из их cron, которые спасают
   от «ноутбук проснулся и выстрелил 8 раз».

**Средне, но заметно:**

6. **Конвейер политик разрешений.** Разобрать нашу эвристику на именованные ступени.
   Это структурно закрывает класс багов, один из которых мы уже ловили руками.
7. **`Ctrl-S` — вброс в идущий ход.** Сейчас у нас очередь ждёт конца хода; вброс
   принципиально полезнее, когда агент уходит не туда.
8. **`ReadMediaFile`** — дать агенту самому смотреть картинки и видео из рабочей папки
   (у нас уже есть весь конвейер вложений, не хватает инструмента).
9. **MCP OAuth** — портировать `mcp/oauth/` (4 файла), закрывает известную дыру.
10. **`enabledTools`/`disabledTools` и `bearerTokenEnvVar`** в конфиге MCP.
11. **`/undo` уровня контекста** — у нас есть rewind по файлам, но нет отката промптов
    вместе с todo и состоянием плана.

**Крупно, обсуждаемо:**

12. **Goal mode.** Самая ценная идея репозитория. У нас есть все части (компакция, чекпоинты,
    рутины, бюджеты) — нет драйвера и автомата состояний. Начинать надо с автомата и
    `<untrusted_objective>`, а не с UI.
13. **AgentSwarm по шаблону** рядом с нашими `TeamCreate`/`SendMessage` — это не замена,
    а второй, более дешёвый режим «одна задача × N элементов».
14. **Документированный REST+WS API вместо ad-hoc Electron IPC.** Дало бы: веб-клиент,
    мобильный доступ, сторонние GUI, и заодно нормальный dev-api. Но это переработка
    транспортного слоя целиком — отдельный разговор.
15. **ACP-адаптер** — вход в Zed и JetBrains без написания расширений.

**Взять как процесс, а не как код:**

16. **Тесты.** 1116 против 0 — это то, из-за чего у нас каждый баг ловится вручную и по одному.
    Vitest на `src/main/agent` и `src/renderer/lib` окупится быстрее любой фичи из списка выше.
